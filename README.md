# ورقة — نرسمها سوا

موقع رسم عربي مستقل، جاهز للاستضافة على GitHub Pages، بدون خادم خاص أو خطوة بناء. إعدادات مشروع `waraqa-4c63e` مضمنة في `firebase-config.js`.

## تشغيل اللعب الجماعي — خطوة مطلوبة

اختبار الاتصال أكد نجاح Anonymous Authentication، لكن قاعدة البيانات الحالية رفضت إنشاء الغرفة بـ `PERMISSION_DENIED`. لم يتم تغيير قواعد مشروعك عن بعد.

1. افتح مشروعك في [Firebase Console](https://console.firebase.google.com/project/waraqa-4c63e/database).
2. اختر **Realtime Database → Rules** لقاعدة البيانات ذات الرابط الموجود في `firebase-config.js`.
3. انسخ محتوى `database.rules.json` كاملًا، ثم اضغط **Publish**. إذا كانت قاعدة البيانات تستضيف تطبيقًا آخر، ادمج مسار `rooms` معها دون إضافة صلاحيات عامة على الجذر.
4. في **Authentication → Sign-in method** تأكد من تفعيل **Anonymous**. نجح بالفعل وقت فحص هذه النسخة.
5. افتح الموقع وأنشئ غرفة. افتح الرابط في جهاز آخر أو متصفح مستقل لاختبار هوية ثانية. تبويبان في نفس المتصفح يشتركان عادة في نفس `auth.uid`.

لا تستخدم قواعد عامة مثل `.read: true` و`.write: true`. إعدادات Firebase للويب ليست مفتاح إدارة؛ الحماية الفعلية في القواعد المنشورة.

## النشر على GitHub Pages

1. أنشئ مستودع GitHub، وارفع **محتويات مجلد waraqa** إلى جذر المستودع، بحيث يظهر `index.html` مباشرة فيه.
2. افتح **Settings → Pages → Build and deployment**.
3. اختر **Deploy from a branch**، ثم فرع `main` ومجلد **/(root)**، واضغط **Save**.
4. انتظر اكتمال النشر وافتح الرابط الذي يعرضه GitHub. روابط الملفات نسبية، فتعمل أيضًا على `https://USERNAME.github.io/REPOSITORY/`.
5. شارك رابط الغرفة من زر «نسخ رابط الدعوة» داخل الاستوديو.

ملفات التشغيل: `index.html`، `style.css`، `app.js`، `sketches.js`، `firebase-config.js` و`.nojekyll`. يمكنك رفع بقية الملفات أيضًا؛ ملف قواعد Firebase الموجود في GitHub لا ينشر القواعد تلقائيًا.

## الميزات

- نمط النصين: رسمة رصاصية خفيفة من 6 رسومات، صاحب الغرفة يسار وصديقه يمين. الألوان تحت التخطيط.
- نمط حر: كلا اللاعبين يرسم على كامل اللوحة. صاحب الغرفة يبدّل النمط ويبدأ لوحة جديدة.
- رصاص، حبر، فرشاة، مائي، ماركر، شمعي، رذاذ، ممحاة، وقطّارة.
- 54 لونًا في ثلاث مجموعات، واختيار أي لون، وحجم وكثافة متغيرة، ودعم ضغط القلم واللمس.
- تراجع وإعادة ومسح خطوطك فقط. لكل لاعب طبقة مستقلة، لذلك الممحاة لا تمس خطوط الآخر.
- حفظ PNG بدقة 1200×900 دون الفاصل وأسماء اللاعبين، ومعرض محلي وتنزيل الرسومات المحفوظة.
- حفظ تلقائي لمسودة الرسم الفردي، واستعادة غرفة الأونلاين من رابطها.
- تصميم متجاوب، واتجاه عربي RTL، واختصارات Ctrl+Z وCtrl+Shift+Z.

## المزامنة والحماية

- `signInAnonymously` ينشئ هوية `auth.uid` محفوظة في المتصفح.
- رمز غرفة عشوائي من 12 خانة hexadecimal باستخدام `crypto.getRandomValues`، ورابط `?room=...`.
- `set` ينشئ الغرفة ويحجز مقعد الضيف. القاعدة تسمح بملء خانة الضيف الفارغة مرة واحدة فقط؛ محاولتان متزامنتان لا تستطيعان الاحتفاظ بالمقعد نفسه.
- `push` ينشئ معرف ضربة قلم، و`set` يحدّثها كل نحو 90ms وأثناء اكتمالها. `onValue` يستقبل تغييرات الغرفة.
- بيانات القلم تستخدم إحداثيات ثابتة مستقلة عن حجم الشاشة. المقاطع الطويلة تقسم لمنع تضخم رسالة واحدة.
- `.info/connected` و`onDisconnect().remove()` يديران حالة الاتصال، مع عقدة مستقلة لكل تبويب. قد يتأخر اكتشاف انقطاع شبكة غير متوقع قليلًا حتى يكتشفه Firebase.
- لا يمكن قراءة غرف الآخرين أو استعراض قائمة الغرف. معرفة الرمز تتيح ملء المقعد الثاني إذا كان فارغًا، فشارك الرابط مع صديقك فقط.
- لا يمكن استبدال المالك أو الضيف، أو حذف الغرفة من العميل، أو تعديل خطوط اللاعب الآخر أو حضوره. اللاعب الثالث يُرفض حتى لو عرف الرمز.
- صلاحيات النصف تُفحص في القواعد، والرسم يُقص بصريًا داخل النصف المسموح. الإحداثيات المشوهة تُتجاهل عند العرض.
- القواعد تتحقق من نوع القلم واللون والحجم والكثافة وحجم رسالة النقاط. إدارة الحصص ومكافحة الإساءة على مستوى الخدمة ليست نظام rate-limiting مخصصًا؛ راقب استهلاك Firebase إذا نشرت التطبيق لجمهور كبير.

الغرف لا تُحذف تلقائيًا. خروج اللاعب لا يحرر مقعده؛ يستطيع الرجوع من نفس المتصفح، بينما إنشاء غرفة جديدة يعطي صديقًا مختلفًا مقعدًا جديدًا. مسح بيانات المتصفح أو تبديل الجهاز يفقد الهوية المجهولة السابقة. المعرض محلي لهذا المتصفح وليس معرضًا سحابيًا. تنزيل PNG يحفظ نسخة دائمة مستقلة عنه.

## الفحص المحلي

يتطلب Node.js:

```sh
npm start
```

افتح `http://127.0.0.1:4173`. لا تفتح `index.html` عبر `file://` لأن JavaScript يستخدم ES modules.

```sh
npm run check
```

لا يحتاج تشغيل الموقع إلى `npm install`. مكتبات Firebase تُحمّل من CDN الرسمي عند استخدام الغرف فقط؛ تعطل الاتصال لا يمنع الرسم المحلي بعد تحميل الصفحة.

## اختبار قواعد الحماية في Emulator

يتطلب Node.js وJava المتوافق مع Firebase Emulator:

```sh
npm install
npm run test:rules
```

اختبار `tests/rules.test.mjs` يستخدم مشروعًا تجريبيًا `demo-waraqa` فقط، ويغطي التنافس على المقعد الثاني، رفض الثالث، خصوصية القراءة، ملكية الخطوط، منع انتحال الهوية، حدود البيانات وحالة الحضور. لم يُنفّذ في بيئة التسليم لعدم توفر Java. يجب تشغيله قبل اعتبار القواعد مختبرة تشغيليًا.

## ما تم التحقق منه

- نجح فحص صياغة ملفات JavaScript.
- تمت معاينة الموقع في المتصفح، وتجربة ضربة قلم والتراجع والإعادة وحفظ الرسمة وظهورها في المعرض.
- نجح تسجيل الدخول المجهول والاتصال بخدمة Firebase. إنشاء الغرفة رفضته قواعد المشروع الحالية؛ لذلك لم يكتمل اختبار المزامنة بين جهازين أو منع الثالث على الخدمة الحية.
